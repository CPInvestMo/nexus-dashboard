## Findings and fixes applied to QA branch

1. **Signed JSON `null`** previously threw because `payload.object` accessed `null`; corrected to return 422.
2. **Null `entry` item** previously threw; corrected to return 422.
3. **More than 100 unique event IDs** previously returned 200 after silently selecting only the first 100; corrected to return 413 before writing dedupe records.
4. **Body-size robustness:** replaced unconditional `request.arrayBuffer()` with a bounded streaming reader that rejects bodies above 64KiB.
5. Extended the `npm test` command to run the complete suite; added a mock-SQLite Durable Object check.

## Privacy and integration limits

- Tests use generated event IDs and a fake test signing key; no real Meta secrets or customer data.
- Signature is calculated over original raw request bytes before JSON parsing.
- Durable Object dedupe tests **simulate** SQL operations; they do not prove production Cloudflare Durable Object behavior.
- No proof of successful hosted challenge, cloud persistence, Meta App subscription, WABA delivery, or background notifications.
- QR/Baileys are excluded from official WhatsApp Cloud API webhook verification.
- Before deployment: secure Cloudflare Free QA account authorization, separate test secrets, explicit permission, then run sandbox-only end-to-end tests. Do not subscribe any production WABA or change the current Outlook appointment agent.
